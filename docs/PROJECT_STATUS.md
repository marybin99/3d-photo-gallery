# 프로젝트 인수 및 구현 현황

확인일: 2026-11-13

## 기준과 미확인 사항

현재 저장소의 README와 소스코드를 기준으로 정리했습니다. 이전 ChatGPT 공유 대화는 접근에 실패했으므로, 그 대화의 요구사항과 결정 사항을 확인한 문서는 아닙니다. 대화 내용을 받은 뒤 아래 개발 순서와 UI 방향을 대조해야 합니다.

## 현재 구조

| 파일 | 역할 |
| --- | --- |
| `src/main.tsx` | 전시 UI, 미니맵, 작품 상세, 방명록, 모바일 입력 |
| `src/Gallery.tsx` | 전시장 지오메트리, 액자, 캐릭터, 이동 경계, 추적 카메라 |
| `src/Character.tsx` | 관절 캐릭터, 보행·정지 전환·대기 애니메이션 |
| `src/locomotion.ts` | 실제 이동량에 따른 몸 방향 회전과 보행 상태 |
| `src/layout.ts` | 로비·전시실 좌표, 벽, 책상, 이동 판정, 공통 시작 위치 |
| `src/data.ts` | 12개 데모 작품의 정보와 3D 배치 |
| `src/supabase.ts` | 선택적 Supabase 연결과 로컬 방명록 저장 |
| `src/styles.css` | 베이지 계열 UI와 모바일 레이아웃 |
| `public/artworks/` | 데모 SVG 12개; 실제 사진으로 교체 필요 |
| `supabase/schema.sql` | 방명록 테이블과 공개 글 조회 RLS 정책 |

기술 스택은 React 19, TypeScript, Vite 7, Three.js, React Three Fiber, Drei, Supabase입니다. 별도 서버, 라우터, 관리자 화면은 없습니다.

## 구현된 기능

- 접속 시 로비에서 시작하는 3인칭 전시장 관람
- WASD/방향키 이동·회전, 사각형 경계 제한, 추적 카메라
- 작품 클릭 상세 보기, 미니맵 위치·방향 표시, 지도 숨김
- 로비 위치 복귀, 조작 안내, 모바일 조이스틱
- 방명록 로컬 저장; Supabase 설정 시 공개 글 조회

후속 요청에 따라 중앙 로비(16 × 16)와 독립 A/B/C 전시실(각 16 × 16)로 확장했습니다. A는 로비 왼쪽, B는 정면, C는 오른쪽에 있으며 출입문으로 연결됩니다. 매 입장 시 로비에서 시작하고 작품은 각 전시실에 4점씩 배치합니다. 로비의 펼쳐진 책을 클릭하거나 가까이서 E 키/책 열기 버튼으로 방명록을 엽니다. 미니맵도 같은 공간 데이터를 사용합니다.

캐릭터는 카메라와 별도로 실제 이동 방향을 향해 최단 각도로 몸을 돌립니다. 전후좌우·대각선 모두 앞으로 걷는 동작을 사용합니다. 실제 이동 거리에 맞춘 팔다리·무릎 보행과 부드러운 출발·정지를 적용했고, 장애물에 막히면 보행이 멈춥니다.

원형 몸통과 벽·책상·문기둥의 충돌, 모서리와 벽을 따른 미끄러짐, 작은 이동 단계로 벽 관통 방지를 처리합니다. 추적 카메라는 벽·문기둥·책상과의 충돌에 따라 거리를 조정합니다. PC에서는 마우스 왼쪽 버튼 드래그로 좌우·상하 시야를 회전하며, A/D와 좌우 방향키는 시야 기준의 좌우 이동입니다. 대각선 이동 속도를 정규화하고 드래그 종료 시 작품/방명록 클릭을 억제합니다. 모바일은 우측 하단 조이스틱으로 자유 방향 이동하며 밀어낸 거리에 따라 이동 속도를 조절합니다. 중앙 데드존으로 손가락 떨림을 무시합니다. 다른 손가락으로 화면을 드래그해 시야를 회전할 수 있고, 터치 취소·포커스 이탈·팝업 전환·화면 회전·크기 변경 시 이동 입력을 해제합니다. 가로의 낮은 화면에서는 조이스틱·상단 정보·미니맵을 축소하고 안전 영역 여백을 적용합니다. 작품 상세는 이미지와 설명을 2열로 배치하고, 방명록·입장 화면은 스크롤 가능하게 유지합니다. `npm test`로 동선·충돌·작품 배치와 이동·마우스 입력을 확인합니다.

## 이번 수정

- Vite 환경변수 타입 선언과 미사용 변수 정리로 TypeScript 빌드 오류 4건 해결
- 방명록/작품 상세가 열린 동안 키보드·모바일 이동 중지
- 입력창 및 버튼의 키 입력과 브라우저 단축키를 이동 처리에서 제외
- 창 포커스 이탈·탭 전환 시 이동 입력 초기화
- 키보드와 모바일 동시 입력 시 이동 속도 제한
- Escape로 팝업 닫기, 작품 상세 대화상자에 접근성 이름 추가

## 남아 있는 작업

README에 기록된 다음 단계이며, 이전 공유 대화에서 최종 확정된 사항인지는 확인이 필요합니다.

1. 운영자 인증·권한, 작품 DB와 Storage, 작품 관리 화면
2. 실제 사진 업로드 및 작품 메타데이터·배치 로딩
3. 서버 검증과 요청 제한을 갖춘 방명록 등록, 숨김·삭제
4. 캐릭터 외형·추가 동작 연출, 실기기 보행·충돌 검증
5. 모바일 실기기 성능 점검, 배포와 도메인 연결

Supabase 직접 INSERT 정책은 없습니다. 프런트엔드는 아직 직접 INSERT를 시도하므로 연결만으로 공개 방명록 쓰기가 완성되지 않습니다. 데모 방명록은 브라우저별로 저장되며 방문자끼리 공유되지 않습니다.

팝업 포커스 이동·가두기·복귀, 3D 리소스 로딩/오류 UI, 실제 사진 종횡비 보존도 추가 점검이 필요합니다.

## 검증

- `npm run build`: 통과
- `npm test`: 동선·충돌·마우스 입력·캐릭터 방향 회전 등 24건 통과. React Three Fiber 장면의 캐릭터 월드 방향 검사 포함
- 번들 크기 경고: JS 약 1.24 MB, gzip 약 358 KB; 코드 분할 검토 필요
- 브라우저 자동 검증: 실행 환경에서 로컬 디버깅 포트 접근이 `EPERM`으로 차단되어 미완료
- 외부 서비스 생성, DB 변경, 배포는 수행하지 않음

이전 대화를 전달할 때는 필수 기능, 확정 UI/전시장 구조, 운영자 흐름, 기술 제약, 마지막 작업 지점을 포함하면 설계를 이어갈 수 있습니다.

## 조작 안내 표시

앱 접속 시 입장 화면 없이 바로 로비를 표시하고 큰 중앙 안내를 띄웁니다. 입장 화면과 나가기 버튼은 제거했습니다. 중앙 안내는, 확인·X·Escape로 닫습니다. 표시 중에는 이동을 중지하고 팝업 안에서 키보드 포커스를 유지합니다. 그 뒤 조작 안내 버튼으로 열면 좌측 하단 버튼 바로 위에 작은 안내를 표시합니다. 화살표 키 모양 아래 W/A/S/D와 이동 방향을 표시하며, 모바일은 우측 하단 조이스틱을 사용합니다.

## 초기 카메라 거리

로비 시작 위치를 `(0, 4.5)`로 옮겨 뒤쪽 벽과 추적 카메라 사이의 여유를 확보했습니다. Canvas 초기 카메라와 이동 중 추적 카메라는 `src/camera.ts`의 같은 좌표 계산을 사용합니다. 첫 프레임과 로비 복귀 시 카메라를 추적 위치로 바로 맞춥니다. 시작 시 카메라 시선 경로가 장애물에 막히지 않는 회귀 검사를 포함합니다.
